# The CourtVision Warehouse

This folder holds `courtvision.duckdb`, the analytics database (not committed to git;
rebuild it any time with `python scripts/ingest.py && python scripts/build_metrics.py`).
Row counts below are for the four default seasons, 2022-23 through 2025-26
(`DEFAULT_SEASONS` in `src/courtvision/config.py`).

## Two layers

**Raw tables** mirror the stats.nba.com API responses exactly (wide, season totals,
`RANK` noise columns included). They are replaced/upserted by `scripts/ingest.py`.

**Views** (`v_*`) are the clean layer everything else reads: the API, the ML models,
and the notebook. Defined in `src/courtvision/metrics/views.py`, recreated idempotently,
always in sync with the raw tables.

## Raw tables

| Table | Grain | Rows | What's in it |
|---|---|---|---|
| `teams` | one per franchise | 30 | id, name, abbreviation, city (static reference) |
| `players` | one per player ever | ~5,100 | id, name, active flag (static reference) |
| `team_season_base` | team × season | 120 | traditional totals: W/L, points, rebounds, assists... |
| `team_season_advanced` | team × season | 120 | efficiency: ORtg/DRtg/net rating, pace, TS%, four-factor stats |
| `player_season_base` | player × season | ~2,260 | traditional totals + games, minutes, `TEAM_COUNT` (traded players) |
| `player_season_advanced` | player × season | ~2,260 | TS%, eFG%, usage, ratings, PIE |
| `game_logs` | team × game (2 rows per game) | ~9,840 | box score per team per game, matchup string, W/L |

Note on traded players: `player_season_*` holds **one row per player per season**,
aggregated across teams, with `TEAM_ID` = last team and `TEAM_COUNT` > 1 as the flag.

## Views (the clean layer)

| View | Grain | Built from | Adds |
|---|---|---|---|
| `v_player_season` | player × season | player base ⋈ advanced | per-game normalization (pts_pg, ...), lowercase names, GP > 0 guard |
| `v_team_season` | team × season | team base ⋈ advanced ⋈ teams | per-game stats + abbreviation in one row |
| `v_team_game` | team × game | game_logs | `is_home` (parsed from matchup), `is_win`, typed game date |

## Schema at a glance

```mermaid
erDiagram
    teams ||--o{ team_season_base : "TEAM_ID"
    teams ||--o{ team_season_advanced : "TEAM_ID"
    teams ||--o{ game_logs : "TEAM_ID"
    players ||--o{ player_season_base : "PLAYER_ID"
    players ||--o{ player_season_advanced : "PLAYER_ID"
    team_season_base ||--|| team_season_advanced : "TEAM_ID + SEASON"
    player_season_base ||--|| player_season_advanced : "PLAYER_ID + TEAM_ID + SEASON"
    game_logs }|--|| game_logs : "GAME_ID (home + away rows)"

    teams { int id PK }
    players { int id PK }
    team_season_base { int TEAM_ID FK; varchar SEASON }
    player_season_base { int PLAYER_ID FK; int TEAM_ID FK; varchar SEASON }
    game_logs { varchar GAME_ID; int TEAM_ID FK; varchar SEASON }
```

Joins to remember: season stats join on `(TEAM_ID, SEASON)` or
`(PLAYER_ID, TEAM_ID, SEASON)`; a game's two rows share `GAME_ID`.
`SEASON` is always the `YYYY-YY` string, e.g. `2025-26`.

## Also in this folder

`models/` holds the trained win-probability artifact (`win_probability.joblib`) and its
metrics sidecar (`win_probability.json`), regenerated by `scripts/train_win_model.py`.
Both are gitignored; the evidence for the model lives in
`notebooks/model_evaluation.ipynb`.

## Poking around

```python
import duckdb
con = duckdb.connect("data/courtvision.duckdb", read_only=True)
con.execute("SELECT * FROM v_team_season WHERE season = '2025-26' ORDER BY net_rating DESC LIMIT 5").df()
```

Any DuckDB client works; the file is a standard single-file DuckDB database.
